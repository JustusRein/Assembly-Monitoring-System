VALIDATION WORKFLOW
1. Close the monitor. Back up the JSONL process logs and move old/demo top-level JSONL files out of logs\process. Do not delete them. Move any old validation_output folder aside too, so stale trials.csv cannot be reused.
2. Run one short pilot, end with q, and inspect the JSONL. Confirm stage_transition rows exist when the UI advances stages and warning_type matches real warning types. Archive the pilot separately so it is not included in the formal results.
3. Record five complete nominal builds with camera/light/fixture unchanged. Then record two wrong-part and two wrong-order runs only if the UI/logger actually records those warnings. Do not score wrong-position trials while position validation is disabled, paused or misaligned.
4. Press q at the end of every run. Press v only for a correctly completed final product when that action is intended.
5. Run analyze_v21_validation.py once after the official runs. Fill validation_output\trials_TEMPLATE.csv using independent ground truth; save as validation_output\trials.csv. Then run the analyser again.
6. Check the report and CSVs manually before using any numbers. Each rate must show x/n. Missing error_elapsed_s means detection latency is unscored. A logged Stage_07 transition is not, by itself, evidence that the final component combination was visually observed.
